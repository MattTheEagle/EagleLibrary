# Eagle Library convention

**Status: contract (milestone M14).** There is no separate version number for the contract itself: it is held by the
Library module version that last changed it, currently `0.1.0`, and every rule below already carries its own milestone.
It describes what the code in `core/catalog.ts`, `core/rules-version.ts` and `core/name-key.ts` does; a test
(`core/library-convention.test.ts`) holds this document against that code. Section 3 lists what is still open, as
accepted residual risk rather than an unresolved question. Only Foundry v13 and the dnd5e system (tested with 5.3.3) are
covered. Version 0.1.0 of the Library needed Eagle Flight Control 0.6.0 (API 0.12.0); version 0.1.1 (2026-09-22, a
compatibility-only patch outside any milestone, triggered by Eagle Homebrew's milestone M2) needs Eagle Flight Control
0.7.0 (API 0.13.0) instead — no rule below changed.

The Library belongs to one world: its compendia are world compendia, created by the game master, and every world has its
own. The Library reads compendia directly; every change goes through Eagle Flight Control (project decision Q3 a, N9).

## 0. Scope

This contract covers what a **consumer module** needs to read Eagle Compendia or copy something into them: recognizing a
compendium, its ruleset version, what counts as the same entry, copying one document or many, rewriting links, and the
subspecies marker (sections 1 and 2). The Library's own **window** (milestone M10), its **copy window** (M11), its
**search field** (M12) and its **search bar/keybinding** (M13) are the game master's own controls for this module; they
are not part of the contract and can change without a contract change.

## 1. Kinds and compendia

Every entry of the Library has a **kind**. A kind is one document subtype (Items and Actors) or one document type (roll
tables, journal entries). There are 19 kinds. Kinds with a ruleset version have two compendia, one per version, the others
one, which makes 34 compendia. Items, NPCs and vehicles carry a ruleset version; nothing else does.

## 2. Rules

| # | Rule | Source |
|---|---|---|
| R1 | **Recognizing an Eagle Compendium.** A compendium is one if all three hold: its package type is `world`, its name is exactly one of the 34 names above (no prefix match, no change of case), and its document type is the one in the table. The label plays no part. A compendium a game master creates by hand under exactly such a name is an Eagle Compendium. | Foundry types: compendium `flags` are always empty and a compendium cannot be renamed (`compendium-collection.d.mts`, `metadata.flags`, no rename method); decision of the project lead, 2026-09-21 |
| R2 | **Which kind a document has.** Items and Actors by their subtype; roll tables and journal entries have one kind each (the pages of a journal entry do not matter). The old Item subtype `backpack` counts as `container`. | M2 discover t1 to t4; dnd5e `module/documents/item.mjs` (migration `backpack` → `container`) |
| R3 | **No kind, no entry.** Actors of subtype `character`, any Item or Actor subtype not in the table, and the document types Adventure, Cards, Macro, Playlist and Scene have no compendium in the Library. A copy of such a document is not made, and the reason is `no-art`. Nothing is guessed. | Decision of the project lead, 2026-09-21 (`m2-hd-1-output.md`) |
| R4 | **The ruleset version of an entry** is the value stored in `system.source.rules`, exactly `"2014"` or `"2024"`, as the compendium index or the raw data gives it. The world setting `rulesVersion` is never used: it is only the initial value of a field nobody has stored yet, so a missing value would read as 2024 in a 2024 world. Absent, `null`, empty and every other value (`"modern"`, `"2015"`, `" 2014"`, a number) mean *not stored*. Kinds without a version ignore the field. | dnd5e `module/data/shared/source-field.mjs` (initial value), `module/settings.mjs`; N7 ("if neither 2014 nor 2024 is stored") |
| R5 | **Once per version.** An entry is the same as another if its key is the same in the same Eagle Compendium and version; it does not matter how the other entry got there. **The key is the pair of the name key (R7) and the requirements key**: the requirements key is the name key of the text in `system.requirements` (a feat's "Wizard 1"), and the empty key when the field is missing, null, empty or not a text; kinds without the field always have the empty key. So `Spellcasting` with the requirement `Wizard 1` and `Spellcasting` with `Bard 1` are two entries, and a second `Spellcasting` with `Wizard 1` is a duplicate. Known limits: 29 of the 67 same-name entries of dnd5e 5.3.3 stay duplicates (same name, same or no requirement), and the same feature written with another requirement (`Bard` against `Bard 1`) counts as another entry. | Decisions Q4 a, Q6 a, **extended by the project lead on 2026-09-21** (`m5-hd-1-output.md`, choice 1); evaluation of dnd5e 5.3.3 `packs/_source` |
| R6 | **Which version a copy goes to.** A stored version is kept; if the name is in that version already, the entry is a duplicate. Without a stored version: 2014; but if 2014 has the name already and 2024 has not, 2024; if both have it, a duplicate. "Has the name" means in the Library's compendium of that version, not in the source. A kind without a version has one compendium, and a name in it makes a duplicate. When a duplicate is forced in anyway, the game master chooses the version. | N7 (wording of the project lead, 2026-09-19); reading confirmed 2026-09-21 |
| R7 | **The name key.** Unicode NFC, every run of white space as one space (JavaScript `\s`, so including the no-break space), no space at either end, lower case. Not changed: accents, typographic against straight apostrophes and quotes, punctuation, language. So `Wanderer’s Pack` and `Wanderer's Pack` are two names, and an entry in another language is another entry. | Decision Q6 a ("same name"); the plan asks for case and spaces only; the language limit is known and accepted |
| R8 | **The name of a forced copy.** `X` becomes `X (Duplicate)`, and if that name is taken `X (Duplicate 2)`, `X (Duplicate 3)` and so on. A name that ends in the suffix already is counted up, not shortened and not extended: `X (Duplicate)` becomes `X (Duplicate 1)`, `X (Duplicate 4)` becomes `X (Duplicate 5)`; if the number is taken, the next free one. Whether a name is taken is decided by the name key (R7). | N8; project lead, 2026-09-21 |
| R9 | **Making the compendia.** The Library never changes Foundry data itself. For each compendium of the table that is missing it asks Flight Control for the request `compendium.create` (`{ type, label, name }` with the document type, label and name of the table), one request at a time, in the order of the table, as the module `eagle-library`. Flight Control runs it on the Gamemaster's client for a Gamemaster or Assistant only; it makes the world compendium and changes nothing else about it (no lock, no ownership). Asking again is safe: a compendium that exists is left alone. The Library stops at the first failure and says where; a name held by a compendium of another document type is reported and not touched. The Library offers this as the Open button of its tab in the Flight Control hub (a dialog with the button "Create missing compendia"); nothing is created without the click. | Contract of Flight Control, section 4 (`compendium.create`, API 0.8.0); decisions of the project lead, 2026-09-21 (`m3-hd-1-output.md`) |
| R10 | **Copying one document.** The source is a primary document in a compendium that is not an Eagle Compendium (one in an Eagle Compendium, one in the world and one inside another document are refused). The Library takes the kind (R2, R3) and the version (R4) from the document and copies it in this order, and stops at the first step that says no, before anything is written: it is refused if the kind has no compendium (`no-art`); if the id of the source is in an Eagle Compendium of its kind already, whichever version (`already-copied`); if the key (R5) is in the compendium of its version (`duplicate`, R6, R7); if that compendium does not exist (`no-target`). Then it asks Flight Control for `compendium.import` (`{ pack, sources }`, the UUIDs of the documents), once. Flight Control keeps the id of every document and where it came from, and clears the folder, the sort order, the ownership and the state; the game system may change a document when it is created (dnd5e removes `gear` from a physical Item outside an NPC and gives a weapon without activities one attack activity). **A container brings everything in it** (the Items whose `system.container` is its id, and in those containers in turn, at most 5 levels deep like dnd5e, at most 100 documents in all) **into the same compendium as the container**, whatever their own kind and version: `system.container` refers to an id in the same compendium, so the contents stay found. The check for a duplicate (R5) and the version (R6) apply to the container only. An Actor takes its embedded Items along in its own data. A source that lies in a container of its own compendium comes without that container: its `system.container` is cleared, because the container is not in the target (a container that lies in another one, too; the contents of a container keep theirs). What the rules or limits refuse goes to the protocol (R11), a duplicate can be forced (R12). No links are rewritten. The Library offers this through `game.modules.get("eagle-library").api.copyDocument(uuid)`, part of this contract; `copyDocument(uuid, { force, version })` (R12). | Decisions N10, Q4 a, Q6 a and of the project lead, 2026-09-21 (`m4-hd-1-output.md`); contract of Flight Control, section 4 (`compendium.import`, API 0.9.0); dnd5e `module/data/item/container.mjs` (`contents`), `module/documents/item.mjs` (`createWithContents`) |
| R11 | **The protocol.** What the rules or limits of the Library refuse is written to the protocol, one entry per source and reason: `duplicate`, `no-art`, `too-many` and `container-too-deep`. Technical failures (`read-failed`, `request-failed`, `unknown-outcome`, `source-not-found`, `source-not-supported`, `no-target`), a repeat (`already-copied`) and the user's own refusal (`not-gm`, `no-flight-control`, `version-required`) are not. The protocol is the text of the world setting `eagle-library.protocol` (JSON: `version`, `dropped`, `entries`); an entry holds the time, the user, the reason, the source (UUID and name), the kind, the version, the target compendium, for a duplicate the UUIDs of the entries that carry the key (at most 5), and its status: `open`, `copied` (the source was copied normally later) or `forced` (copied by force), with the UUID of the copy. Asking again for the same source and reason updates the entry. At most 500 entries and 250,000 characters are kept; beyond that the oldest done entry goes first, then the oldest, and `dropped` counts them. The Library reads the setting itself and writes it through Flight Control (`setting.write`, with what it read, so that a change by another client is noticed); a second try follows a failed write, and a write that fails twice is reported as `protocol: { written: false }`, not as a failure of the copy. A text that cannot be read is replaced, and the console says so. | Decisions Q5 a, N7, and of the project lead, 2026-09-21 (`m5-hd-1-output.md`, choices 2 and 3); contract of Flight Control, section 4 (`setting.write`, API 0.10.0) |
| R12 | **Forcing a copy.** `copyDocument(uuid, { force: true, version })` copies a **duplicate** anyway (only that: `already-copied`, `no-art`, the limits and every failure stay as they are, and a source that is no duplicate is copied normally). The copy is named `X (Duplicate)` by R8, from the names in the target compendium whatever their requirements, and gets a new id that the Library makes; the id is given with the request, so asking Flight Control again with the same id writes nothing twice. The version is the Gamemaster's choice (N7); without it the stored version of the source; a kind with a version and no stored version needs the choice (`version-required`, nothing is written); a kind without a version ignores it. A container is forced with new ids for the container and every content, the container named `X (Duplicate)`, and each content pointing at its new container (`system.container`), in one request. An Actor takes its embedded Items along unchanged. Where a document came from stays (N10); links from the copy to itself (`effects[].origin`) point at the source until the links are rewritten (milestone M6). The open protocol entry of the source becomes `forced`. | Decisions Q5 a, N7, N8; `m5-02-apply-output.md`, section D |
| R13 | **Rewriting links (the logic; milestone M6).** Pure functions in `core/uuid.ts`, `core/link-map.ts` and `core/rewrite-links.ts`; the copying does not use them yet (milestone M7). **What is a link:** every Compendium UUID in the data of a document, in any field and in any text (`@UUID`, `@Embed`, a UUID by itself, a set or list of UUIDs), in the form with a type (`Compendium.<package>.<compendium>.<type>.<id>`) and in the older form without it (`Compendium.<package>.<compendium>.<id>`); UUIDs of the world and relative ones (`.<id>`) are none. Only the main part is read and changed: embedded parts and an anchor stay as they stand. **The map** is from the main part of a copied source to the main part of its copy in an Eagle Compendium: from the results of the copying (`copied`), for a duplicate that was skipped from the first entry of the protocol that carries the key (`existing`), or from a plan (`planned`); a forced copy is not in the map (other documents point at the entry that carries the key, R12). **Rewriting:** every link the map knows is rewritten, always into the form with a type; a link of a document to itself (`self`) goes to its copy whatever the map says, so the links of a forced copy to itself point at the duplicate; a link that points into an Eagle Compendium stays, so a second run changes nothing; relative links and local ids stay. **Origin (N10):** `_stats.compendiumSource`, `_stats.duplicateSource`, `flags.core.sourceId` and `flags.dnd5e.sourceId` stay on the source, in a document and in the documents embedded in it; `effects[].origin` is rewritten. **Report:** every link that does not end in an Eagle Compendium is named with its path: `not-copied`, `no-art`, `package-missing`, `target-missing`, `unresolvable`; it is left as it is (N11). The data that is given is never changed. | Decisions N6, N10, N11; `m6-02-apply-output.md`; evaluation of dnd5e 5.3.3 `packs/_source` (`m6-01-discover-output.md`) |
| R14 | **Links when a document is copied (milestone M7).** The links of a copy are rewritten **when it is written**, in the same request: no document is written twice and an interrupted run leaves no half rewritten copy. **Pass 1** makes the map of the run: every document the run writes (the source and, for a container, its contents, also when forced) maps to the UUID its copy will have (the ids stay, or the Library has made the new ones); a linked document whose id is in an Eagle Compendium of the same document type maps to that document (`copied`; this finds the contents of a container in the compendium of the container); a duplicate that was skipped maps to the first entry of the protocol that carries the key (`existing`). What no source covers stays as it is and is reported (`not-copied`, `no-art`, `package-missing`, `target-missing`; since milestone M8 what a document links to is copied too, R17). **Pass 2** reads the data of each source, rewrites it with the rules of R13, and sends the changed fields as `changes` of the entry of the request (`compendium.import`, at most 50 paths for an entry). A change inside a list is sent as the **whole list**, never as a place in a list, and a path under another path is dropped; over the limit every path is reduced to the first field. The container field is set after the links. A link of the document to itself points at its own copy (a forced copy: at the duplicate), links of other documents to a forced source at the entry that carries the key. **Report:** the answer of `copyDocument` has `links` (`total`, `counts`, at most 50 `problems` with path and UUID, `truncated`) and `map`; `api.checkLinks(uuid)` gives the same for a document that is in an Eagle Compendium and changes nothing. Copies made before this rule keep their links to the sources; they are not rewritten afterwards (decision of the project lead, 2026-09-21, `m7-hd-1-output.md`). | Decisions N6, N10, N11, `m7-hd-1-output.md`; `m7-02-apply-output.md`; contract of Flight Control, section 4 (`compendium.import`, API 0.11.0) |
| R15 | **The spell lists of the Library (milestone M7).** A spell list is a page of type `spells` of a journal. When a journal is copied, the UUID of each of its spell list pages **in the copy** (`Compendium.world.eagle-journals.JournalEntry.<id>.JournalEntryPage.<id>`) is entered in the world setting `eagle-library.spell-lists` (JSON `version` and `pages`, at most 200, none twice, the oldest go first), written through Flight Control (`setting.write`, with what was read, a second try); a journal without spell lists leaves the setting alone; a write that fails is reported as `spellLists: { written: false }` and the copy counts. **Every client registers** the pages with dnd5e at every start (`ready` hook, only under dnd5e): `dnd5e.registry.spellLists.register(uuid)` for each page, a page that fails is logged and the others go on, nothing is thrown, and the console says `spell lists: N registered, M failed`. dnd5e merges lists of the same type and identifier: a list of the Library adds to the list of the same name of dnd5e (for example `class:wizard`) and does not replace it, so a spell that is in the original **and** in the Library is listed twice (with the UUID of the original and of the Library). **A module that shows spell lists filters them to the spells of the Library.** | Decision of the project lead, 2026-09-21 (`m7-hd-1-output.md`, choice 2); dnd5e 5.3.3 `module/registry.mjs` (`SpellListRegistry.register`, merging), `module/data/journal/spells.mjs` |
| R16 | **Where a copy comes from (milestone M8).** The four fields that name the origin of a document (`_stats.compendiumSource`, `_stats.duplicateSource`, `flags.core.sourceId`, `flags.dnd5e.sourceId`) stay on the source (N10, R13). The Library does not record the origin of a copy anywhere else and does not change the source label of a Library compendium; whether Foundry or dnd5e shows the source book of a Library copy right is only checked (Live-Check F of milestone M8), and a rule is made only if it does not. | Decision m8-hd-1 (origin: check only); `m8-02-apply-output.md` |
| R17 | **The closure of a copy (milestone M8).** `copyDocument(uuid)` copies, with the document, **everything it links to** in the sources of other compendia (fields and text alike, links found the way R13 finds them), and what those link to, until nothing new is found: the closure. Every document of the closure is decided like the first one (kind, version, already copied, duplicate, target, container with contents); a document of the closure is **never forced**, and its version is the stored one. What is in the Library already (same id and document type) is not copied again and the links go to it; a duplicate is not copied and the links go to the entry that carries the key (`existing`), also when the first copy of the key is itself in this run. `no-art`, `package-missing` and `target-missing` documents of the closure are only reported (`closure.skipped`), a duplicate, `too-many` or `container-too-deep` document of the closure is also protocolled (R11). The closure is read first and nothing is written before it is known: more than `maxDocuments` (default 5,000) documents give `closure-too-large` and write nothing; `{ closure: false }` copies the first document and its container contents only (the behaviour of M7). **Portions:** the documents are written in portions of at most 100 documents to one compendium each (a container and its contents stay in one portion), each portion one `compendium.import` request; the map of the whole run is known before the first portion, so every link is rewritten when its document is written. The run stops at the first portion that fails (`closure: { documents, written, remaining }` in the failure); asking again continues, because what is written counts as `already-copied`. The protocol and the spell lists (R15) are written once for the run. The progress is logged (`closure of <uuid>: portion i of n`). `api.plan(uuid, options)` gives the closure without writing (`documents`, `portions`, `byCompendium`, `dependencies`, `skipped`). | Decision m8-hd-1 (closure: all links); `m8-02-apply-output.md`; contract of Flight Control, section 4 (`compendium.import`) |
| R18 | **Subspecies (milestone M8).** dnd5e keeps a subspecies as an Item of its own; nothing in the data ties it to the species. The Library marks species Items (kind `species`) with the flag `flags.eagle-library.subspecies = { species, origin }` (`origin`: `"auto"` or `"manual"`), set **when the copy is created**, in the same request (a `changes` path, after the links and the container field). **Auto rules, nothing else is guessed:** (1) a name of the form `Species, Subspecies` with exactly one comma and both parts filled: the species is the part before the comma; (2) else a `system.type.subtype` that is filled, is not the name and stands in the name as a word: the species is the subtype with a capital letter; (3) else no marker. A marker that the source has already is kept. dnd5e 2014 gives Half-Elf and Half-Orc the subtypes `elf` and `orc`, so they get a marker; it is a suggestion of the data and can be removed. **By hand:** `api.setSubspeciesMarker(uuid, species)` (`origin: "manual"`), `api.removeSubspeciesMarker(uuid)` and `api.readSubspeciesMarker(uuid)` on a species Item in an Eagle Compendium; the write is the Flight Control request `compendium.flag` (own namespace, world compendium, unlocked). Existing copies get no marker afterwards. | Decisions N12, N21; m8-hd-1 (narrow type for own flags); `m8-02-apply-output.md`; contract of Flight Control, section 4 (`compendium.flag`, API 0.12.0) |
| R19 | **Copying many at once (milestone M9).** `copyCompendia(selection)` copies every document with a kind (R2) from one, several, or — with `"all"` — every non-Eagle compendium of the world (system, module or world, treated the same); `selection` is a compendium name, a list of them, or `"all"`. Each document is copied on its own through the unchanged `copyDocument` (full closure, R17); `already-copied` and `duplicate` are expected outcomes and stop nothing. Only after several failures **in a row** (default 5, a call option `{ maxConsecutiveFailures }`, not a rule of its own) does the whole run stop (`stopped: true`, `stoppedReason: "consecutive-failures"`), or when `{ signal }` (a standard `AbortSignal`) is already aborted (`stoppedReason: "aborted"`); a repeat call with the same selection continues where the last one stopped, because what was already written counts as `already-copied`. `planCompendia(selection)` gives the exact size first, without writing anything: a shared, in-memory running state keeps a dependency that several roots of the selection point at from being counted twice, the way the closure of a single document (R17) already avoids counting it twice within itself; it can be aborted the same way. Both take a `{ onProgress }` callback, called once per candidate, in addition to the console. No new request type to Flight Control: this rule only calls `copyDocument`/`compendium.import` again. | Decisions of the project lead, 2026-09-22 (`m9-02-apply-output.md`: consecutive-failure stop, exact dry run with shared dependencies); contract of Flight Control, section 4 (`compendium.import`, unchanged) |

## 3. Unverified

Almost everything below was open only until its own milestone's live check confirmed it; each point says which one did.
What is still open at the end of the phase is listed as **accepted residual risk**, not as a question waiting on an
answer — the project lead has already seen and accepted it (M8), or it is a candidate for the next phase to check early.

- **Confirmed live, during the phase's live checks:** the compendium index returns no value for `system.source.rules`
  where nothing is stored, and shows the old Item subtype `backpack` as `container` after the migration (R2, R4;
  milestones M3/M4). Foundry accepts the 34 names in `createCompendium` and gives a world compendium the package type
  `world`, and a new world compendium's state (`locked: false`, ownership `PLAYER: OBSERVER`, `ASSISTANT: OWNER`) is as
  expected (R1, R9; Live-Check B). Copying one document (R10; Live-Check C): the ids of embedded documents and where
  they came from stay, the Gamemaster's client may write into a world compendium this way, and dnd5e finds the contents
  of a container in the compendium of the container. Forcing and the protocol (R11, R12; Live-Check D): Foundry keeps an
  id given for a copy and applies `changes` to the data, a missing `system.requirements` reads the same way in the
  index, and the protocol holds up as a world setting at real size. Rewriting links and the spell lists (R13, R14, R15;
  Live-Check E): dnd5e reads a rewritten link (an Item Grant, a `@UUID`), a link into a compendium that is not active
  still shows, and the registry takes pages of a world compendium. Origin, closure and subspecies (R16, R17, R18;
